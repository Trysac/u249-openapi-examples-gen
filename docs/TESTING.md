# Testing

## Tools

- [Vitest](https://vitest.dev/) runs the suites in `test/`.
- Tests import from `../src/index.js` and `../src/cli.js`.
- CLI tests mock stdout and stderr with `vi.fn()` and write temporary files under the OS temp directory with the prefix `openapi-examples-gen-`.

## Commands

```sh
npx vitest run
npx vitest
```

## Rules

- Assert observable behavior: return values, exact output strings and thrown errors.
- Keep tests deterministic: no network calls and no real clock or randomness.
- Temporary files go to the OS temp directory.
- Each bug fix adds a test that fails without the fix.

## Tiers

The repository contains two local Vitest suites and no conformance suite.

### test/index.test.ts

Covers `generateExample` for the required object example with `email`, optional `firstName` and `age`; scalar values including integer bounds and `multipleOf`, number, string length bounds, boolean, enum and const precedence; string formats `date-time`, `date`, `uuid`, `ipv4` and `ipv6`; `fillExamples` adding examples deterministically without mutating input and leaving existing examples unchanged; cyclic required versus optional properties; property-name heuristics and pattern failure; `validateExamples` numeric and format messages; a schema with only `$ref`; OpenAPI 3.1 `type` array with `string` and `null`; unicode examples; parameters with existing `examples` being skipped; `ExamplesError` construction and code; `maxDepth`; the 100,000 node limit; array `uniqueItems` and `minItems` limits; numeric exclusive bounds; null, nullable, unknown types and unknown formats; arrays; optional property omission; property-name normalization; `allOf`, `oneOf` and `anyOf`; escaped local `$ref` pointers; unresolved references; and `fillExamples` traversal of parameters, request bodies and responses.

### test/cli.test.ts

Covers `run(['check', file], io)` returning 1 and writing each issue as `pointer: message`; a clean check returning 0 and writing nothing; `fill` writing `JSON.stringify(result, null, 2) + '\n'` and returning 0; input over 10,000,000 bytes returning 2 and writing `input_too_large`; usage errors and unknown commands returning 2; invalid JSON returning 2 and writing `invalid_json`; non-object documents returning 2 and writing `invalid_document`; and read errors returning 2 and writing `error`.

## Reports

Coverage output, when enabled, is generated by Vitest. The repository contains the two test files described above.
